# Persona entry template — v1

The quality bar. Every Side 1 persona must be able to fill every section of this template, or it
doesn't ship. If a persona can't fill it, it gets merged into one that can, or cut.

Two gate tests before an entry is even drafted:
1. **The retell test** — could a non-expert hear the name once and retell the scenario to a colleague?
2. **The sorting test** — can you point at one person and one moment? (If not, it's a Side 2 condition,
   not a persona.)

---

## [Persona name — 6 words max]

**One-liner:** A single sentence a CFO or HR lead understands with zero security background.

**The scene:** 3-5 sentences of narrative. A person, a moment, a decision. This is the part people
retell — write it like a story, not a finding.

**The axes:**
| Axis | Value | Note |
|---|---|---|
| Actor | | |

| Recoverability | | per impact class if mixed |

**Maps to:** OWASP LLM Top 10 (2025) entry/entries; NIST AI RMF function where relevant.

**Siblings:** Other personas in the same OWASP category, and what distinguishes this one
(usually a different intent — that's the point of the framework).

**Conditions that feed it:** Which Side 2 conditions make this persona more likely or more damaging.

**How you'd notice:** 2-4 observable signals, written plainly. What would actually show up — in a
dashboard, a bill, a log, a hallway conversation.

**What stops it:** 3-5 controls, ordered from most to least effective. Named plainly enough that a
non-technical leader could ask "do we have this?" in a meeting.

**The honest caveat:** Every persona oversimplifies something. Name the oversimplification here so
critics don't get to.
